## 四套机制与 HAU 归属

Contribution 记录价值，Reward 分配现实价值，Honor 保存共同价值记忆，Progression/Achievement 记录成长体验。一级归属均为 HAU，不拆分 Human/Representative/Private Agent 的贡献比例；现实奖励支付对象可为 Human，组织记录仍属 HAU。更换 Agent 不丢失历史。

Contribution 是 HAU 行为对组织实现当前或未来 Goal 的能力产生的可追溯正向变化。Change、Positive Impact、Traceability 三项成立才进入 Ledger；工作时长、Token、任务数不等于贡献。Task Success ≠ Contribution；Task Failure ≠ No Contribution。

## Seed Categories 与共享事实

Result、Learning、Capability、Protection、Enablement，加 Other/Emerging 构成 5+1 种子分类；允许多标签，不冻结最终贡献本体。候选贡献可来自 Task、Execution、Knowledge、Capability、Goal 层，但解释必须追溯 Event、Result、Dependency 或 Downstream Impact，不能以自我声明创造事实。

先让真实工作发生并记录，再估值。贡献识别基于共享 Organizational Reality；Observation、Challenge、发现风险、能力外化或复现都可能产生价值，不依赖结果被 Selection。

## Cycle Collective Valuation 与事件盲评

每个 Cycle 整理 Contribution Events、Evidence、Goal Impact、Downstream Impact 与 Context，HAU 参与 Collective Valuation，原则上不评价自己的贡献。评价具体 Event，而不是给 Contribution Type 预先定价，更不是评价喜欢哪个 Human。

Blind Event Valuation 尽可能隐藏 HAU Identity：先看 Event、Evidence、Goal/Downstream Impact，再 Reveal Ownership → Reward。可随机或分层抽样，避免每人阅读全部事件。隐藏身份的可行性、抽样人数、周期、排序/分点方式均不预设数值。

Scarcity/Saturation 提供同类贡献数量、过去周期变化与当前组织稀缺程度，帮助 Human 判断 Marginal Organizational Value；不自动按公式折价。重复行为仍可能有价值，稀缺信号反映当前需要。

## Reward 与下游影响

Collective Valuation → Reward Pool Allocation；不预设某类 Result/Knowledge/Protection 的固定价格。Reward follows Contribution，不用奖励价目表定义贡献。周期历史可以形成 Organizational Value Model，但稳定性须观察。

Downstream Impact 可以随知识复用、工具组合或后续结果增长，原 Event 不变，价值解释可变化。Impact can propagate; reward does not automatically propagate：保留完整影响关系，奖励由当前 Cycle 评议决定，不沿因果链自动永久分成。

## Honor 与成长

Honor 是 Human 集体选择保存、供未来成员记住和效仿的行为记忆。候选来自 Ledger、AI Detection 或 Human Nomination；无每月配额，一个 Cycle 可以没有 Honor。故事保存 Context、Challenge、Action、Impact、Why We Remember，并可增加后续章节。

同类行为大量出现后，可能不再有足够 Novelty/Historical Significance 成为 Honor，但不意味着行为不好，Badge 仍可记录经历。Honor 纪念 Event，不做 Human 排名。

Progression 表达长期成长旅程；Achievement/Badge 记录事件里程碑、探索与反馈。等级及徽章设计留待真实行为之后，等级存在与否仍属 Experimental。不得把 Contribution+Capability+Reliability+Badge 加权包装成综合绩效等级。

Progression/Badge 不影响 Capability、Task Access、Permission、Risk Authority，也不直接修改 Human Model；只有底层行为 Evidence 支持模型演进。Reward 或大贡献不能购买 Authority。

## 实施与实验

M1 先运行 Contribution Ledger，M2 再引入 Collective/Blind Valuation、Scarcity/Saturation、Reward Pool、Honor 和成长体验；取代早期“第一阶段先 Honor Wall”的顺序。先观察基线，再改激励；重要机制变化记 Policy/Product Change Event。串票、联盟、偏差与价值文化均需真实观察，不能声称盲评已消除这些问题。

## 激励压力测试补充

大量Observation、Hypothesis或Candidate只是活动/学习信号，未通过Change、Positive Impact、Traceability不能按数量生成正式Contribution。重复已知失败不自动是探索贡献，Explorer类Badge也不能只按失败次数授予。Enablement以Blocked、帮助提供的Tool/资源、恢复及结果等可追溯关系为依据，互相声明不够。

保存谁评价哪个Contribution的事件，便于后续观察Reciprocal Voting Pattern；发现异常产生Governance Signal，不提前宣称复杂反串谋算法已存在。激励若持续损害Goal，可产生IncentivePolicyChallenge，经Policy治理调整Reward/Honor机制。盲评不能被当成消除社交偏差的证明。
