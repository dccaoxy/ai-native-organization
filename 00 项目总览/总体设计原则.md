# 总体设计原则

## 1. 目标、任务与工作分层

- **Goal**：我们要让什么结果发生。
- **Task**：为了推动 Goal，现在需要交付什么。
- **Work**：Human 与 Agent 在 Task 内部自由决定如何把交付物做出来。

Goal 与 Task 是组织级对象；Work 是 Active Task 内部的 Free Work Space，不是同等级的重型对象。Goal 不写 Solution；Task 不写死 How；Work 在边界内保持最高自由度。

## 2. Protocol 固定，Workflow 动态

组织严格定义对象、边界、确认、验收、重试、升级与留痕规则，但不要求所有工作遵循同一条固定路径。

## 3. Human 与 Agent 都是组织中的 Actor

Human 和 Agent 都可以 Proposal、拆解、执行或 Review；具体角色由任务、风险、可验证性和能力决定。Human 保留目标激活、责任承担以及超越授权边界的最终决策权。

## 4. 边界之内默认自主

Human 或 Agent 在 Task 内部只受三项约束：不偏离 Task、不突破 Boundary、最终产生可验收的 Output + Evidence。在此范围内，拥有选择 Workflow、Agent Calls、Tools、Temporary Subtasks、Exploration 与 Collaboration 的自主权。

Temporary Subtask 默认不进入 Task Bus；只有需要独立 Executor、独立资源、独立 Acceptance、跨成员协调、独立追踪或对 Goal 产生重要影响时，才升级为正式 Task。

## 5. Human 管 Boundary，不审批每一步

管理注意力集中在目标、资源、风险、重大判断和机器无法可靠闭环的地方。正常 Routing、Retry 和 Failover 尽可能由系统处理。

## 6. Output + Evidence，而不是忙碌

工作价值通过可验收交付物及其证据判断，不以工时、会议次数或过程动作替代结果。

## 7. Submitted 不等于 Completed

执行者只有提交权；结果必须经过独立 Review 和授权 Acceptance 才能关闭。

## 8. 学习嵌入工作

Work → Feedback → Learning → Retry → Capability Upgrade。Task、Review、失败和知识复用共同构成新人能力形成过程，而不是把学习放在工作之外。

## 9. 允许探索，也防止 Goal Drift

Task Graph 可以随 Evidence 动态生长；但每个新 Task 必须说明如何推进 Parent Goal，否则应转为新的 Goal Proposal。

## 10. 自动留痕，人只记录关键判断

系统自动记录 Agent、Knowledge、Artifact、Evidence、Decision、状态和资源消耗。Human 只在 Decision、Exception 与 Knowledge Confirmation 等关键节点主动输入。

## 11. 失败必须产生组织价值

失败不是简单标签。Failure Record 应保留尝试、证据、原因和可复用教训，并回流到 Knowledge、Capability、Routing 与下一轮 Task。

## 12. 不消灭所有 Human Friction

争论、解释、求助、共同解决困难和冲突修复虽然低效，却可能产生 Trust。组织不能把人的连接完全外包给 AI。

## 13. 组织认知与行为权力分开

Store broadly, activate sparsely；Knowledge Activation ≠ Context Injection；Inject cognition, not workflow。可信度、显著性、行为权力分别治理。前期 Learn before prescribe，提升无 Learned-Knowledge 干预任务比例，不削弱现行安全规则。

## 14. Human 与 Agent 共同治理

不要统一 Intelligence Layer，统一 Organization Runtime Layer。Runtime = Protocol + State + Interface；注册、绑定、权限、Lease、Progress、Query、OTA 与 Audit 形成接入骨架，详细治理仍待设计。
