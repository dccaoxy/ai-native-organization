# 统一工作台：10 分钟试用路线

本地入口：http://127.0.0.1:8877。这是合成测试工作台，不是线上站点或真人 Pilot；浏览器中的 H1/H2/H3 是测试角色。数据库保留之前的试用记录，本轮连续验收没有向它导入或覆盖数据。

## 1. 启动和连接

在仓库目录运行：

```powershell
python -m organization.workspace
```

默认继续使用 `.autodev/unified/workspace.sqlite3`。如果端口已占用，先确认之前的工作台终端；不要重复启动或改端口，不要再次传 `--seed-from`。

打开上述地址，在本机把 `.autodev/unified/workspace.key` 内容粘贴到控制密钥栏，然后点击“连接”。可在本机用 `Get-Content .autodev/unified/workspace.key | Set-Clipboard` 复制，不必发给聊天或写进 Git。连接成功后密钥输入框会清空。

## 2. 看清组织闭环

选择 H1/H2/H3 观察各自“下一步”待办。展开一个正式 Return，核对对应 Execution 和唯一负责 Human。Review 是可信度判断，Acceptance 是任务标准验收，Selection 才是选择采用；已有记录会展示历史，不需要为了演示重复提交。

## 3. 看清知识变化

在学习区对比“候选解释（历史判断）”与“知识版本与变化”。旧版本可能曾通过验证，但现在已经失效或被替代；应以知识版本的当前状态判断能否复用。展开失效影响、修订理由、新任务及能力包替代关系，核对旧能力包仍失效、新能力包有单独复现记录。

## 4. 试一下表单和接续

打开一个学习表单，选择已有引用，观察证据/旧版本/任务字段自动带入。只填写草稿，点击“刷新状态”，确认内容仍在；切换 Human 后应看不到上一角色的草稿，切回来恢复。退出或整页刷新会清除未提交草稿；已提交的组织记录在数据库中持久保存。

如有离线 Agent，先实际确认客户端已经可运行，再由所属 Human 点击“确认 Agent 已恢复”，填写恢复说明并恢复 Execution。按钮只记录运行状态，不会启动客户端。不要为试按钮而更改无关执行。

## 5. 让 Agent 完整跑一遍

可运行 `python -m organization.continuous_demo`。它会新建临时隔离数据库，从零 Execution/Knowledge 开始：4 个独立客户端注册、浏览器授权与验收、知识形成、失败反馈、新任务重验；中途重建服务两次并验证事件不变。不会改上面的统一工作台数据库。

依赖 Python、Node 和 Playwright；本机 Node 可通过 `--node` 指定，依赖目录通过 `--modules` 指定，设置 `$env:LAB_BROWSER_CHANNEL='msedge'` 使用已安装 Edge。完整可复制运行命令见 `UX02_ACCEPTANCE.md`。

自动验收使用确定性 Agent 脚本和浏览器扮演的合成 Human，未调用模型，不代表真人体验或组织业务效果已验证。

## 给开发者的反馈

只需记录：在哪个区域、选择哪个测试 Human、做了什么、预期看到什么、实际看到什么。不要附控制密钥。下一轮优先修复“找不到下一步、状态看不懂、角色权限混淆”等实际问题；上线和真实参与者试点仍需单独决定。
